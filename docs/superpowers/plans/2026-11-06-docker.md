## 设计与边界

- Python 3.11 CPU 镜像，安装系统运行库、CPU PyTorch 和原 requirements；只 COPY 应用与配置源文件。
- 单进程 uvicorn 工厂入口，非 root UID/GID 10001。保留现有 main.py CLI 与 create_app(pipeline) 兼容性。
- 应用 lifespan 在后台线程构建 Pipeline；/health 始终只返回进程存活，/ready 从 initializing/503 转为 ready/200，初始化错误保持 failed/503。业务入口未就绪返回 503。空知识库可就绪。
- 容器专用工厂调用 Settings.from_env()，读取显式本地模型路径并校验基础文件，再复用 main.build_pipeline；启动时预加载真实 Cross-Encoder，不评分、不调用 LLM，无 Mock 降级。
- 只读挂载整个 Hugging Face hub（保留 snapshots→blobs 相对引用），通过容器内 snapshot 路径选择已存在模型；设置离线与禁用遥测。已发现当前两个缓存版本分别为 7999e1d3359715c523056ef9478215996d62a620 和 2cfc18c9415c912f9d8155881c133215df768a70。
- 原始知识库只读挂载 /app/knowledge；上传与 manifest 独立读写挂载 /app/data/uploads；不向评测或历史目录写入。
- Compose 使用运行时 env_file 传入现有 API_KEY/OPENAI_API_KEY/MODEL_NAME/BASE_URL，不设置新的 Provider 默认值。不读取真实 .env；示例只写占位符。

## 验证边界

当前未发现 PATH 或标准 Docker Desktop 路径下的 docker.exe，故预计只能完成静态与本地进程测试。不得为验证安装 Docker、下载模型、调用真实 LLM 或运行四方案实验。镜像包安装属于 Docker 构建依赖安装，不是模型权重下载；本机不执行构建命令替代容器验证。

## 审查后的裁定

- 健康与就绪接口采用异步状态读取，避免共享工作线程池占满后探针超时；已通过线程池耗尽的 RED → GREEN 回归。
- 保留宿主机 8000→容器 8000，默认额外限定宿主机绑定地址 127.0.0.1。容器内部仍按用户要求监听 0.0.0.0；当前没有认证，局域网开放须由演示者明确调整。
- 模型元数据和权重文件仅检查存在性，没有真实加载；本地工厂 Smoke Test 使用 fake embedding/scorer/LLM，不能替代容器实测。
