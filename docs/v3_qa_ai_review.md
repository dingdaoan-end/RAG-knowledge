# V3 QA 两轮 AI 辅助评审报告

日期：2026-10-27。评审者：Codex AI（**非独立人工评审**）。

已逐份评审 197 个既有真实 DeepSeek 答案：第一轮 32 份证据不足答案，第二轮 165 份可回答问题的成功答案。所有评审均对照实际交给模型的上下文正文，再核对冻结参考答案和关键事实；没有重新调用生成 API，没有改答案、标签或生产代码。

## 规则与身份边界

沿用 `docs/day8_qa_evaluation.md` 和 `app/evaluation/qa_review.py`：三个维度各自 0/1/2，不合成总分；逐项关键事实给 true/false 与答案原文；无依据断言列出原文、具体理由和实际 context ID；Evidence Sufficiency 使用已有 `insufficient_evidence_handled`。

Faithfulness 只核对该答案的实际 context，不能用全库其他 Chunk 补证。Correctness 对照冻结参考答案与教学语料，缺少事实不直接算事实错误；本轮没有额外取得厂商文档的独立权威认证。CUDA 1175/1176 只按项目示例日志理解，不作为官方通用错误码定义。

负例中，说明不能确定并指出具体缺失信息，可判不确定性处理合格；不强制有“请提供”三个字。但没有说明取得当前实测/识别核验/计时对照/编码输出的事实，仍会在关键事实覆盖中扣除。故不确定性处理合格不等于所有补证行动都完整。

可回答标签为 true 的记录沿用原工作流，`insufficient_evidence_handled=null`（本轮负例专项指标不适用），实际上下文局部不足通过忠实度、切题性、覆盖和 notes 明确记录，不把参考标签改成 false。

每条新评审 `reviewer=Codex AI（非人工评审）`，`status=completed` 仅表示 AI 评审字段完成。原 `results/v3_qa_review/*.json` 的 197 条 pending 保持不变。新专用摘要只使用 `ai_review_metrics`，不得冒充人工评分；旧通用 `summarize` 会把任何 completed 记录统称“人工”，因此不能把其该名称直接用于声称本轮完成了人工认证。

## 具体案例与失效归因

### qa_031：候选已召回，Top-3 丢掉必要组件

BM25 候选中 `embedding_bge` 排第 6，实际上下文是 `pdf_ocr, hybrid_fusion, api_stream`，回答：“资料只说明文本经过清洗、切块后进入 Embedding 流程，但**没有明确说明它把什么转换成什么**。”

其他三方案的实际上下文同时含 `pdf_ocr` 与 `embedding_bge`，答出“图片→文字”和“文本→稠密语义向量”。BM25 的 F/R/C=2/1/2、覆盖1/2，其他三者2/2/2、覆盖2/2。它不是编造错误 Embedding 定义，而是排序及 Top-3 截断造成任务不完整。

### qa_035：四方案共同缺口，重排未补回

四方案实际 Top-3 都没有 `embedding_bge`，均只能说明 FastAPI 的 HTTP 职责，未完成向量化职责比较，F/R/C=2/1/2、覆盖1/2。

Vector/Hybrid/Reranker 的候选10中有该 Chunk（Vector/Hybrid 候选排名8），却没有进入最终上下文；BM25 的候选10本身没有它。因此同一道题在 BM25 包含召回缺失，其他三方案主要是排序/截断问题。不能把所有失败笼统叫 LLM 幻觉。

### qa_040：完整链路需要多证据，统一 Top-3 成为瓶颈

全部方案候选10内都已有 `chunk_overlap, embedding_bge, faiss_ip, rag_overview`，但实际 Top-3 缺少切块和文本向量化的定义。Vector/Hybrid/Reranker 各覆盖2/4，BM25仅覆盖1/4（还缺 RAG 提示词资料）；四者切题性均1、忠实度及事实正确性均2。

例如 Hybrid 明说：“尤其没有提供‘切块’和‘向量表示’的具体步骤及其在流程中的位置”。这是忠于实际上下文的部分回答，不能算整题答完。该题参考依赖四个不同 Chunk，而统一上下文预算为3，本身就限制多证据覆盖；只提高精排分数不必然解决。

### qa_041：BM25 的关键词资料不能替代语义表示定义

BM25 的 `embedding_bge` 候选排名4、没有进 Top-3；答案承认“没有进一步展开语义向量匹配的具体帮助”，覆盖2/3、切题性1。其余三方案覆盖3/3、切题性2。这也是可定位的上下文选择差异，不是已证实的事实错误。

### qa_032：证据存在，生成仍可能漏事实

四种方案都给了 `transformer_attention`。只有 Hybrid 的答案明确说“以建模上下文关系”，其余三份只说通过 Q/K/V 与其他 Token 交互。按逐项事实规则，交互动作与建模目的分开：后三者这一项覆盖false，但都回答了题目主要所问的表示和权重来源，切题性仍2。

特别是 Vector 与 Hybrid 的实际来源顺序完全相同，答案却有该差别。因此这里不能把覆盖差异归功于更好的检索；属于生成表述差异，并保留语义边界供复核。

### qa_042：不应把过时直接等同一律无法回答

Hybrid 答：“**如果资料不足或已过时，应明确说明无法回答**”。原始 `rag_limits` 说资料过时可能导致错误、应核查来源，`rag_evidence` 才在资料不足时要求不能回答；二者不能直接合成“一旦过时就必须拒答”。本轮记 F/R/C=1/2/1，列一条无依据条件扩展；不是整个回答错误。

Vector/Hybrid/Reranker 此题的实际上下文内容与顺序相同，其他答案把拒答限制在“缺乏答案或资料不足”。这项差异是生成解释，不支持“Hybrid 检索算法更差”的因果结论。对建议性语句是否应扣事实分有评审边界；若后续人工认为仅需措辞提醒，Hybrid 在共同40题的事实均分可由1.975变为2.000，不应把本次极小差距包装成稳定胜负。

### qa_043：来源归因的局部争议

Hybrid 表格写：“**资料明确提到输出‘注意力权重’**”（JSON中引文使用答案实际的中文双引号）。实际正文仅说明权重来自缩放点积及 softmax，没有明确定义 Self-Attention 最终输出形式。本轮记忠实度1，并列原文归因过强；答案随后明确最终上下文表示形式未说明，故没有把它判成“最终只输出权重”的核心事实错误，事实正确性仍2。

Vector 明确“资料没有明确描述 Self-Attention 的最终输出形式”，Reranker 写“资料明确的是注意力权重……未进一步说明最终输出形式”，按限定充分均为2。BM25此题调用失败。此措辞边界应优先人工复核；不在共同40题的对比中，也不据它宣称总体质量变化。
